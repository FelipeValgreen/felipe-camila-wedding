# DEFINITION_OF_DONE.md — Cierre del caso Felipe & Camila

**Fecha:** 14 de agosto de 2026

El Centro de Gestión se considera `DONE` para el caso real sólo cuando producto, datos, operación y resiliencia cumplen estas condiciones.

## Producto

- [ ] módulos P0 operativos desde UI sin necesidad habitual de Supabase Console;
- [ ] ninguna acción visible es falsa;
- [ ] móvil y desktop permiten completar los journeys críticos;
- [ ] estados vacíos/errores tienen acción clara;
- [ ] Copiloto no inventa ni ejecuta sin confirmación.

## Invitados / RSVP

- [ ] respuestas originales preservadas;
- [ ] cada persona contabilizable tiene ficha o incidencia consciente;
- [ ] no existen +1 implícitos;
- [ ] restricciones están asociadas a personas;
- [ ] relaciones `confirmed`/`probable` están diferenciadas.

## Mesas / Salón

- [ ] todos los asistentes finales tienen estado de seating explícito;
- [ ] cero sobrecapacidad no aceptada;
- [ ] cero asignaciones duplicadas;
- [ ] grupos fuertes separados sólo con decisión consciente;
- [ ] layout final representa montaje acordado;
- [ ] plano/exportación offline disponible.

## Operación

- [ ] tareas críticas cerradas o aceptadas;
- [ ] presupuesto/proveedores/pagos críticos actualizados;
- [ ] cronograma day-of final;
- [ ] música/cues críticos finalizados;
- [ ] documentos/contratos necesarios disponibles;
- [ ] contactos day-of definidos.

## Calidad

- [ ] lint/typecheck/build verdes;
- [ ] suite mínima de dominio verde;
- [ ] E2E de mutaciones críticas ejecutado en staging aislado;
- [ ] responsive P0 validado;
- [ ] accesibilidad crítica validada;
- [ ] no quedan P0 funcionales conocidos.

## Seguridad

- [ ] secretos fuera de Git;
- [ ] RLS/grants revisados;
- [ ] RBAC aplicado a endpoints mutantes;
- [ ] Preview no escribe producción;
- [ ] no hay credenciales históricamente comprometidas todavía aceptadas;
- [ ] Sheet productiva con acceso limitado;
- [ ] logs saneados.

## Resiliencia

- [ ] backup reciente verificado;
- [ ] restore ensayado en staging;
- [ ] sync observable y recuperable;
- [ ] exportaciones offline T-24;
- [ ] Wedding Day Runbook revisado;
- [ ] contingencia sin Internet entendida.

## Release

- [ ] documentación canónica coherente;
- [ ] changelog/roadmap reflejan estado real;
- [ ] PR final aprobado;
- [ ] deployment productivo `READY`;
- [ ] smoke post-release verde;
- [ ] `WEDDING_DAY_READY` alcanzado antes del evento.

## Comercialización posterior

No forma parte del cierre Felipe/Camila:

- multi-wedding completo;
- billing;
- marketplace;
- portal de proveedores generalizado;
- onboarding comercial.

Esas capacidades se planifican después de cerrar el caso real y probar un segundo matrimonio.
